# 消息路由与会话生命周期

> 面向非读者,讲清两件事:一条微信消息怎么到达 agent、一个会话怎么生老病死。

---

## 路由:微信用户 → 机器人 → 项目 → 会话

```
  微信用户
     │  把消息发给哪个"机器人"?
     ▼
   机器人
     │  查这个机器人属于哪个"项目"
     │
     ├─ 未绑定 / 项目停用 ──▶ 丢弃
     │
     └─ 已绑定 ──▶ 项目
                     │
                     │ 一个项目只有一个会话
                     ▼
                   会话
                     │
                     ▼
          agent 处理,回复只回给发起者
```

- 一个机器人只属于一个项目;一个项目可绑多个机器人。
- 一个项目只有一个会话,所以多个用户/机器人共用同一份上下文。

---

## 会话生命周期

```
   项目启动(创建 / 恢复)
     │  恢复"最近那个"会话;第一次就新建一个
     ▼
   [会话 S]
     │
     ├─ 普通消息 ─▶ 进 S,agent 处理
     ├─ /new     ─▶ 换成新会话 S'(旧上下文抛弃)
     ├─ /compact ─▶ 压缩 S(仍是 S)
     ├─ /abort   ─▶ 中止当前任务(仍是 S)
     └─ daemon 重启 ─▶ 恢复成"最近那个"(可能是 S')
```

- 项目启动时绑定一个会话;普通消息始终进这同一个会话。
- 只有 `/new` 或 daemon 重启(恢复成最近那个)会改变要进哪个会话;
  `/compact`、`/abort` 只是作用于当前会话,不换会话。
- 项目忙时,普通消息直接拒绝、不排队,不进会话。
